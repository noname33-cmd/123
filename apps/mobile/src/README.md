# Truck profile form

`TruckProfileForm` использует `@truck/truck-profile` и явно предлагает оба типа: rigid truck без прицепа и tractor с одним semitrailer. По умолчанию тип и числовые значения не заданы. Имя, внешние габариты (m), текущая полная масса (kg), все физические оси обязательны. Для состава измерения относятся ко всему составу с грузом; масса включает топливо и людей, число осей включает подъёмные.

Доступны явные режимы m/kg, ft/lb, in/lb и ft+in/lb. Начальный режим — m/kg; тип транспорта и значения пусты. Каждый режим хранит отдельный черновик всех полей в памяти: переключение не переименовывает единицы введённых чисел и не выполняет обратную конвертацию. При возврате черновик восстанавливается; выбранный тип транспорта общий. В ft+in/lb каждый габарит имеет отдельные поля целых неотрицательных футов и десятичных дюймов [0,12). Оба поля обязательны: для отсутствующего компонента нужно явно ввести 0; общая длина должна быть положительной. 12 дюймов отклоняются без автоматического переноса в футы. Это правило формы записи, не дорожный максимум. В других US режимах поддерживаются десятичные футы либо полные дюймы. Запятые, разделители тысяч, дроби со slash, суффиксы и scientific notation отклоняются.

Перед проверкой контракта US inputs преобразуются в SI через feetToMeters/inchesToMeters/feetAndInchesToMeters/poundsToKilograms. Успешная проверка показывает точные нормализованные SI значения без округления. Масса и габариты не преобразуются в float; BigInt используется только внутри арифметики. Только целое десятичное представление осей преобразуется в number и проверяется как positive safe integer. UI не повторяет физические или дорожные ограничения провайдера.

Validate profile проверяет формат через общий parser; успешный результат сбрасывается при редактировании или смене типа. Черновики остаются в памяти. В App подключён TruckProfileStore: Save сохраняет один проверенный снимок, Restore восстанавливает его в m/kg, Delete удаляет запись и оставляет текущую форму. Все операции явные; валидация сама по себе не сохраняет данные. Формат, ошибки, native prerequisites и границы — в `storage/README.md`. API, auth, routing или GPS не добавлены.

Проверки из корня: `pnpm --filter @truck/truck-profile build`, затем `pnpm --filter @truck/mobile typecheck`, `lint`, `test`, `build`. Для чистой установки root Turbo build/test/typecheck выполняют build зависимостей автоматически. Тесты взаимодействия покрывают оба типа, незаданный тип, успешный ввод и сброс успеха после некорректного редактирования. Это component tests, не device E2E.
