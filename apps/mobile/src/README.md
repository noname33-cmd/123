# Truck profile form

`TruckProfileForm` использует `@truck/truck-profile` и явно предлагает оба типа: rigid truck без прицепа и tractor с одним semitrailer. По умолчанию тип и числовые значения не заданы. Имя, внешние габариты (m), текущая полная масса (kg), все физические оси обязательны. Для состава измерения относятся ко всему составу с грузом; масса включает топливо и людей, число осей включает подъёмные.

Доступны явные режимы m/kg, ft/lb, in/lb и ft+in/lb. Начальный режим — m/kg; тип транспорта и значения пусты. Каждый режим хранит отдельный черновик всех полей в памяти: переключение не переименовывает единицы введённых чисел и не выполняет обратную конвертацию. При возврате черновик восстанавливается; выбранный тип транспорта общий. В ft+in/lb каждый габарит имеет отдельные поля целых неотрицательных футов и десятичных дюймов [0,12). Оба поля обязательны: для отсутствующего компонента нужно явно ввести 0; общая длина должна быть положительной. 12 дюймов отклоняются без автоматического переноса в футы. Это правило формы записи, не дорожный максимум. В других US режимах поддерживаются десятичные футы либо полные дюймы. Запятые, разделители тысяч, дроби со slash, суффиксы и scientific notation отклоняются.

Перед проверкой контракта US inputs преобразуются в SI через feetToMeters/inchesToMeters/feetAndInchesToMeters/poundsToKilograms. Успешная проверка показывает точные нормализованные SI значения без округления. Масса и габариты не преобразуются в float; BigInt используется только внутри арифметики. Только целое десятичное представление осей преобразуется в number и проверяется как positive safe integer. UI не повторяет физические или дорожные ограничения провайдера.

Validate profile проверяет формат через общий parser; успешный результат сбрасывается при редактировании или смене типа. Черновики остаются в памяти. В App подключён TruckProfileStore: Save сохраняет один проверенный снимок, Restore восстанавливает его в m/kg, Delete удаляет запись и оставляет текущую форму. Все операции явные; валидация сама по себе не сохраняет данные. Формат, ошибки, native prerequisites и границы — в `storage/README.md`. API, auth, routing или GPS не добавлены.

Проверки из корня: `pnpm --filter @truck/truck-profile build`, затем `pnpm --filter @truck/mobile typecheck`, `lint`, `test`, `build`. Для чистой установки root Turbo build/test/typecheck выполняют build зависимостей автоматически. Тесты взаимодействия покрывают оба типа, незаданный тип, успешный ввод и сброс успеха после некорректного редактирования. Это component tests, не device E2E.


## Design 01 — первый перенос в RN

App использует нейтральный фон и карточку профиля; theme.ts содержит navy/forest-green цвета. ActionButton использует Pressable, переносимый текст без фиксированной высоты, минимум 48 layout units, selected/disabled accessibility states. Основные Validate/Save выделены зелёным; остальные действия вторичные. Это не полный перенос трёх HTML-экранов: главная и вход не добавлены.

Все четыре режима единиц, пустое начальное состояние, точные значения, разделённые черновики, parser и локальное хранение сохранены. Синтетические значения макета не подставляются. Ключи/refs и native iOS input adapter не изменены. Сообщения об отсутствии routing/GPS остаются видимыми. Форма прокручивается вместе с действиями; sticky footer пока не вводился. iOS input сохраняет существующую высоту 48 и native font17; системный крупный шрифт требует отдельной проверки.

Локально: mobile typecheck/lint/test (22 теста), build (Android/iOS JS bundles) успешно. Это не APK/Xcode build и не device E2E. Native визуальный контроль, VoiceOver/TalkBack, крупный шрифт, клавиатура и disabled touch на устройстве не выполнены: локальный эмулятор/Metro/API остановлены, Docker status недоступен. Провайдер авторизации не выбран; аккаунты и токены не реализованы.


### Android: клавиатура и шрифт 130%

17 октября 2026 на emulator-5554/API35 проверены системный font_scale1.3, ввод имени при видимой IME, доступность Validate и Save/Restore/Delete прокруткой после закрытия клавиатуры. Снимки просмотрены: имя над клавиатурой, нижние кнопки и ошибки читаются. Масштаб1.0 восстановлен через finally. Проверялось поле имени; десятичная клавиатура, другие IME, 200%, screen readers и iOS этим сценарием не покрыты. Saved snapshot не изменялся. Ошибки типа транспорта/полей теперь используют error/errorSurface (#923e31/#fff0ec); успешная проверка сохраняет зелёную подложку и явный текст. Валидация/контракт не изменены. Финальные mobile22 tests/typecheck/lint passed; новые native binaries не собирались.


### Android: фокус числового поля

Проверка обнаружила перекрытие массы цифровой клавиатурой. Android ProfileInput теперь измеряет свою windowY при onFocus и передаёт её через форму в App; ScrollView прокручивает поле к верху видимой области с отступом16. iOS native adapter, refs/defaultValue/ключи сессий и обработчики текста не изменены. KeyboardDidShow/KeyboardAvoidingView варианты не решили проверенный случай и удалены. Снимок decimal-keyboard-fixed.png и XML подтверждают полное поле с точной массой30000.123456789 выше IME (bounds103,668–979,794 на1080x2400). Ввод выполнен Android input-командами, не ручными нажатиями клавиш.

Component test проверяет передачу координаты без изменения черновика/валидации. Mobile23 tests, typecheck/lint и обе JS-сборки проходят. Это не native build/iOS regression. Переключение фокуса при уже открытой клавиатуре, другие IME и сочетание этого изменения с130% отдельно не проверены.


На окончательном focus-scroll коде повторён полный Android numeric сценарий: все6 точных полей, SI summary, Save enabled после Validate и disabled после дописывания9 к массе. Snapshot writes не выполнялись. Unit23/typecheck/lint/обе JS-сборки success. Нативные APK/Xcode/CI остаются непроверенными.
