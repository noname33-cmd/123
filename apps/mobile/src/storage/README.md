# Local truck profile snapshot

`TruckProfileStore` — интерфейс load/save/remove. `JsonTruckProfileStore` валидирует границу и зависит только от `KeyValueStorage`. `AsyncStorageProfileStore` — отдельный адаптер `@react-native-async-storage/async-storage` 3.1.1, база `truckprofiles`, единственный ключ `truck-route-savings.saved-profile`. Native модуль загружается только по явному действию пользователя; отсутствие модуля или I/O error даёт unavailable, без fallback на фиктивное успешное сохранение.

Формат: `{storageVersion: 1, profile: TruckProfile}`. Profile schemaVersion отдельно равен 1. Все габариты в m и масса в kg — точные decimal strings; единицы ввода и незавершённые черновики не сохраняются. Поддерживаются оба типа транспорта. JSON и профиль повторно проверяются при чтении; unknown fields/units/types, повреждённая запись и несовместимая версия не принимаются и не удаляются автоматически. Миграций пока нет. Save повторно валидирует snapshot и заменяет предыдущую запись только по явной команде. Delete удаляет только этот ключ, не clear всей базы. Ошибки наружу не передают исходный текст/данные исключения.

Save доступен после Validate; изменение формы снимает валидацию. Restore явный, не автоматический: восстанавливает тип и нормализованные SI поля в m/kg, заменяя m/kg draft; другие unit drafts сохраняются в памяти. Delete оставляет текущую форму. Кнопки сериализованы через pending guard; редактирование/смена режима/валидация блокируются на время I/O. После размонтирования запоздалый ответ не изменяет UI. Успех показывается после завершения операции, не заранее.

AsyncStorage — локальное **незашифрованное** хранилище, не vault и не backend. В нём нет токенов, API-ключей, GPS/location history, аккаунтов или sync. Авторизация и ownership не реализованы и не обходятся; сохранение на устройстве не подтверждает road legality. Системный backup/перенос устройства и uninstall/reinstall отдельно не проверены; обещаний secure erase или сохранности после удаления приложения нет.

Проверка совместимости перед установкой: [официальная документация AsyncStorage 3.1](https://react-native-async-storage.github.io/3.1/) — RN iOS/Android >=0.76, Kotlin >=2.1.0, Android min SDK 24, iOS >=13, MIT. Здесь RN 0.84.0, Kotlin 2.1.20, min SDK 24 и iOS target RN >=15.1. API createAsyncStorage/getItem/setItem/removeItem сверены с документацией и установленными types. Это заявленная совместимость; результаты фактических native checks отдельно в `docs/audit.md`.

После frozen install требуется **native rebuild**: прежний APK не содержит AsyncStorage. Android: из apps/mobile/android `gradlew.bat resolveDependencyLocks assembleDebug -PreactNativeArchitectures=x86_64 --max-workers=2 --no-daemon` (на Windows ASCII checkout/SDK/JDK как в mobile README). На macOS: `bundle exec pod install --deployment`, затем обычный Xcode build/test. На Windows iOS build не выполняется. Реальная iOS integration подтверждена macOS [CI run 39023269817](https://github.com/noname33-cmd/123/actions/runs/39023269817), commit 935ce045b80ed4c9621e2360955f588f2719ee0c: deployment pod install, native build, shell и save/restart/restore/delete/restart/empty XCTest прошли. Точные SI строки проверены, screenshot восстановленного профиля просмотрен. Проверенная конфигурация: iPhone 16 / iOS 18.5 / Xcode 16.4; physical devices, быстрый ввод, reboot, backup и release не проверялись. CI assertions/deployment lock enforcement сохранены.

JS-проверки: `pnpm --filter @truck/truck-profile build`, `pnpm --filter @truck/mobile typecheck`, `pnpm --filter @truck/mobile lint`, `pnpm --filter @truck/mobile test`, `pnpm --filter @truck/mobile build`. Store tests используют память/отказы I/O; adapter unit test использует mock native API и не доказывает дисковую запись. Device persistence проверяется отдельным сценарием save → force-stop/start → restore → delete → force-stop/start → empty.
